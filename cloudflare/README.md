# Cloudflare Pages viewer

Public, read-only count viewer for **这个词在外刊中**. The desktop app pushes
keyword occurrences to a Cloudflare Pages Function protected by a per-pair
client key.

## Pairing model

One pair = one Pages project + one KV namespace + one client key.

- Each pair has an independent `.pages.dev` URL and isolated counter data.
- The client key is generated locally and only its SHA-256 hash is stored as a
  Pages environment variable (`CLIENT_KEY_HASH`).
- The desktop app stores the raw key in its local settings and sends it as a
  Bearer token when syncing.
- The public viewer can read aggregate counts and timestamps without a key.
  Treat the `.pages.dev` URL as public.
- A pair is intended for one desktop client. Creating more independent clients
  means deploying more pairs.

## Local deployment

Prerequisites:

- Node.js 20+
- A Cloudflare account with Pages + Workers KV permissions
- `npx wrangler login`

From the repository root:

```powershell
node --version
npx --yes wrangler whoami
pwsh .\cloudflare\deploy-pairs.ps1 -Count 3
```

The script:

1. generates a high-entropy client key per pair;
2. creates a KV namespace;
3. creates an independent Pages project;
4. writes a per-pair Wrangler config with the KV binding, pair name, timezone,
   and key hash;
5. deploys the static frontend and Pages Functions;
6. verifies `/api/verify` with the generated key;
7. writes local pairing metadata to `cloudflare/pairs.local.json`.

`pairs.local.json`, `cloudflare/.deploy/`, and `.dev.vars` are git-ignored.

## Desktop app setup

For each pair, open the desktop app:

1. Go to **设置 → Cloudflare 查看器**.
2. Paste the pair URL (for example `https://waikan-view-01.pages.dev`).
3. Paste the `key` value for the same pair.
4. Click **测试连接**. The app should show the pair label.
5. Turn on **启用云端同步**.

The app stores the URL and key in `%LOCALAPPDATA%\Waikan\settings.json`.
The key is a write credential for that one pair; do not share it. Keys are
generated by `deploy-pairs.ps1` and saved only in `cloudflare/pairs.local.json`.

Existing local history is queued during the database v1 → v2 migration and is
uploaded on the first sync. Every event has a stable ID, so retries are
idempotent. Deleting a local record does not delete an already-uploaded cloud
record.

## API

All write endpoints require:

```http
Authorization: Bearer <client-key>
```

### `GET /api/verify`

Returns the pair name and timezone. Useful for the desktop “test connection”
button.

### `POST /api/events`

```json
{
  "events": [
    {
      "id": "2f5112bce0b94f238e0b3e2e922d8c84",
      "at": "2026-10-29T14:21:08.000+08:00",
      "localDay": "2026-10-29",
      "hour": 14,
      "source": "microphone"
    }
  ]
}
```

Limits: 500 events per request, 1 MB body, 500 retained detailed events per
day. Daily totals are kept for 3 years; per-event timestamps older than 180
days are pruned to keep the single KV value within the free-plan limit.

The day snapshot is stored under a single KV key (`snapshot:v1`) per project.
This keeps reads and writes cheap on the free plan. The app sends batches in
order and only marks local rows synced after a successful response.

### `GET /api/stats?days=90`

Public summary used by the viewer: today, range totals, daily series, hourly
distribution, weekdays, source mix, streaks, last sync, recent events.

### `GET /api/day?date=YYYY-MM-DD`

Public day detail with individual timestamps.

## Frontend

`public/` is a dependency-free HTML/CSS/JS dashboard:

- editorial dark/light theme;
- daily trend chart with 7/30/90 day ranges;
- 90-day activity heatmap;
- hourly distribution;
- source breakdown, streaks, recent timestamps;
- per-day detail dialog and CSV export;
- auto-refresh every 45 seconds.

No external CDN or telemetry. All assets are served from the same Pages
project.

## Free-plan notes

- Views/timestamps are public if someone knows the URL.
- The client key grants write access to that pair only.
- The sync endpoint accepts independent event IDs, making retries idempotent.
- Cloudflare KV is eventually consistent; the viewer may lag a few seconds after
  a sync.
- For a private viewer, put Cloudflare Access in front of the Pages project, or
  extend the API with a read token.
